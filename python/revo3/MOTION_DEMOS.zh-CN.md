# Revo3 动作演示

四个 Python 示例使用 SDK 2.x 的 `Manager -> Hand` 接口，面向 21 关节 Revo3 手型。
默认只做离线预览，不导入 SDK、不连接设备。实机执行必须加 `--run`。
当前内置姿态是空载候选值，已做部分右手实机试跑，尚未完成全关节验收；左右手需要分别校准，不能仅凭角度限位判断手指之间不会干涉。

| 入口 | 展示内容 |
| --- | --- |
| `opposition_demo.py` | 拇指对掌，以及拇指依次向食指、中指、无名指、小指靠拢 |
| `finger_function_demo.py` | 逐指屈伸、爪形抓取、握合、展收指、逐指侧摆 |
| `gesture_dance_demo.py` | 张掌、展指、握拳、V 手势、逐指波浪 |
| `servo_classic_demo.py` | 经典正弦 servo 往复，支持关节选择、幅度、频率和滤波参数 |

从仓库根目录运行；先激活已安装相应版本 SDK 的 Python 环境（源码维护使用 `py310` 环境）。

```bash
# 离线预览，不需要安装 SDK
python python/revo3/opposition_demo.py
python python/revo3/finger_function_demo.py
python python/revo3/gesture_dance_demo.py
python python/revo3/servo_classic_demo.py

# 导出右手对掌候选姿态；文件已存在时拒绝覆盖
python python/revo3/opposition_demo.py --side right --export-profile /tmp/opposition-right.json

# 编辑并检查姿态后，指定设备执行；替换端口和设备地址
python python/revo3/opposition_demo.py --profile /tmp/opposition-right.json --side right --port /dev/ttyUSB0 --slave-id 127 --run

# 手势舞：减速至 0.5 倍，执行两遍
python python/revo3/gesture_dance_demo.py --tempo 0.5 --repeat 2 --side right --port /dev/ttyUSB0 --slave-id 127 --run

# 经典 servo：仅食指屈伸关节，0~30°，0.25 Hz，4 个周期
python python/revo3/servo_classic_demo.py --joints 13 14 15 --maximum 30 --frequency 0.25 --cycles 4 --side right --port /dev/ttyUSB0 --slave-id 127 --run
```

连接复用 `Manager.connect_auto()` 的发现机制，可用 `--port` 和 `--slave-id` 限定目标。
连接后检查 21 关节布局和 `--side`；左手使用 `--side left`，不支持把右手姿态简单取反后宣称已适配左手。
内置左右手模板使用相同候选逻辑角度，`side` 用于阻止误用，不代表完成了左右手分别标定。
Pro、Basic 等非 21 关节布局会被拒绝。

## 姿态配置和对掌校准

前三个 demo 支持 `--export-profile` 和 `--profile`，配置包括：

- `schema_version`：固定为 `1`。
- `kind`：`opposition`、`finger` 或 `dance`，必须匹配入口。
- `side`：`left` 或 `right`，必须匹配命令行和实机。
- `calibrated`：默认 `false`；用于记录人工标定状态，不是软件或硬件认证。
- `steps`：动作列表。每步包含 `name`、21 项 `positions_deg`、过渡秒数 `duration`、停留秒数 `hold`。

四指逻辑顺序为小指 J0~J3、无名指 J4~J7、中指 J8~J11、食指 J12~J15，
各指依次为 `[Abd, MCP, PIP, DIP]`。拇指 J16~J20 为 `[Rotation, MCP, IP, Abd, Flex]`。
动作配置始终使用逻辑关节，不使用底层通道编号。

校准时先保留张手和单个对掌步骤，以较低节奏逐步调整拇指及目标手指角度；确认指间距离后再扩展到完整序列。
四个对指姿态独立调整。内置模板只表达运动意图，不计算指尖空间坐标，也不使用触觉闭环判断接触。
对掌完成、抓取成功、握持力及防碰撞效果都需要实机验证。第一版不做带物体的自动抓握，也不做音乐节拍同步。

## 连续舞蹈和错峰对掌

内置手指功能、手势舞和对掌配置使用 `streaming: true`，由主机连续发送 MIT 位置和速度目标。
手势舞直接衔接抓握和爪形，波浪使用相邻手指交叠的平滑脉冲，幅度为 60°/60°/45°；
只在对掌和 V 手势等展示点停留。舞蹈中的对掌四指屈伸比拇指晚启动 0.2 秒，独立对指入口快速段延迟 0.15 秒，接近终点时平滑减速。
这些轨迹不检测接触，不保证指尖相碰，也不用于带物体抓握。

配置可选字段：`streaming`（布尔值）；每步 `finger_delay`（四指屈伸延迟秒数，必须小于过渡时间）；
`motion: "wave"`（三轮连续波浪，必须从前一步的张开姿态开始，当前步目标也必须为张开）。
波浪默认总时长 6.5 秒；`duration` 按比例缩放波形。旧配置未指定这些字段时仍使用原有分段路径。

测试时可显式使用 `--skip-joints 2 12 20` 排除已确认故障关节。前三个入口支持此参数，并切换至连续发送路径；
被排除关节的 Kp、Kd、前馈电流和目标速度均为零，不再主动保持，回位误差检查也排除它们。
只允许跳过指定关节的堵转故障；新故障、电气故障和系统错误仍停止运行，不自动扩展跳过列表。
默认不跳过任何关节，不清故障、不解除软件急停。

## 执行和结束行为

所有目标在首个动作前按设备位置限位检查，并根据速度限位延长过短的轨迹。
分段路径从实际反馈开始，句柄成功后等待 0.25 秒检查 Health 和终点误差；超过 5°则停止。
连续路径从有界初始姿态开始，按前一目标衔接，运行中约每 0.25 秒检查 Health，每次发送检查位置和速度限位。
它不为每个动作等待反馈到位，只在最终回位检查未排除关节的误差是否超过 5°。
连续发送请求间隔约 10 ms，受 Python、Health 查询和链路时序影响，不保证实时频率；命令超时为 500 ms。
软件急停或零力模式开启时拒绝运行。异常后尝试软件急停，不自动继续动作。
`--tempo` 缩放动作和停留时间，速度限位仍有效；不会改变经典 servo 的 `--frequency`。

正常执行结束后，平滑返回启动时读到的姿态：

`--feedback-tolerance-deg` 默认 `0`，可显式设置为 `0~2`，用于接受零位附近小幅越界的实际反馈。
它不放宽目标限位：越界但在容差内的初始反馈，其保持及返回目标取最近的合法边界，运行时打印调整值。
例如反馈 -0.2°、下限 0° 时，启用 0.5° 容差后返回目标为 0°。超出容差仍拒绝动作。

- `--finish hold`（默认）：保留最后轨迹命令的 `kp/kd`；不额外写入卸力模式。关闭连接后是否持续保持需要结合固件验证。
- `--finish relax`：回位后显式开启零力模式，该设备状态可能在连接关闭后保留。

`--kp` 默认 `1.0`，`--kd` 默认 `0.1`，均允许 `0~10`。
脚本不自动解除软件急停、清除设备错误或恢复零力模式；运行前确认设备处于可运动状态。

运动异常、等待超时或 Ctrl+C 中断时，取消当前轨迹或关闭 servo 会话，并尝试软件急停；不会继续舞蹈，也不会自动回位。
急停尝试等待最多 3 秒，失败会明确打印。软件急停不能替代独立停机手段；异常后应读回状态，再决定是否恢复。
返回码 `0` 表示预览/导出完成或动作执行成功，`1` 表示错误，`130` 表示键盘中断。

## 与 1.x servo 的关系

旧版给全部 21 个关节发送同一组 0~40°、0.5 Hz 的正弦目标，按 100 Hz 请求下发，
使用二阶临界阻尼滤波 `omega=25`，结束时发零位、`kp=1/kd=0` 并等待 0.5 秒。

新版保留正弦往复、请求发送率和滤波参数，默认幅度改为 0~60°、频率 0.75 Hz、3 次，使用 `ServoSession.send_mit()`，
默认只运动四指的 12 个屈伸关节，其余关节保持启动姿态。统一 0~40°不适合部分侧摆关节，不能直接恢复为全部关节默认值。
`--joints` 可指定逻辑关节，但目标和峰值速度必须通过设备限位检查。

滤波在示例主机端实现为二阶临界阻尼，每个采样间隔按常目标精确更新，同时输出位置与速度；
`--omega 0` 关闭滤波。2.x `ServoSession` 本身不暴露旧版的全局滤波配置，因此这不是旧版滤波实现的逐点复刻。
波形从最低点、零速度开始，先平滑进入，再执行完整周期，最后平滑回初始姿态。
位置单位为 degree，速度为 rpm，前馈电流为 0 mA。

请求发送率 `--rate` 默认 100 Hz，可设 1~200 Hz；Python 和实际链路不保证实时频率。
错过的采样周期会跳过，不补发积压目标。命令超时默认 200 ms，发送失败即退出并尝试急停。
